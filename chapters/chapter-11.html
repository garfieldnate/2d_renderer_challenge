Chapter Eleven

Images and Resampling

A gradient is a function you can evaluate at any point, to any precision. A photograph is not. It's a fixed grid of pixels, and the moment you want it at any size or angle other than exactly as stored, you have to invent the colours that fall between the ones you have. That inventing is resampling, and it splits into two opposite problems that no single filter solves: making an image bigger, where you're guessing detail you don't have, and making it smaller, where you have too much detail and have to throw it away without it turning to sparkle. This chapter builds both, and it slots the image straight into chapter 10's paint: an image is a function of position too, it's the one you look up instead of compute.

The image plugs into everything you already have. It's a paint, so paint_fill draws it through coverage exactly as it drew a gradient. It stores premultiplied linear-light pixels, the chapter 9 representation, because filtering is averaging and averaging transparency any other way brings back the dark halo from chapter 9. And it's placed on the canvas by a chapter 4 matrix. The only genuinely new idea is which direction you walk: not from the source pixels forward, but from the destination pixels back, through the inverse of that matrix, asking each output pixel where in the image it came from.

§ 11.1 An image is a grid of pixels

Reading an image is chapter 1's PPM writer run backwards. read_image(ppm) parses the header, and for every pixel decodes its three bytes from sRGB back to linear light — the same decode that chapter 1 defined and never used until now — and stores an opaque premultiplied pixel. A photo you saved in chapter 2 comes back in the space the renderer works in. image_texel(img, ix, iy, extend) reads one texel by integer coordinates, and when the index falls outside the image the extend mode folds it back: clamp holds the edge texel, repeat wraps for a tiling pattern, reflect bounces so the tile meets itself without a seam. Same three modes as a gradient's, one dimension up.

§ 11.2 Sampling, and the half-pixel offset

Now the guessing. To draw the image bigger, most output pixels land between stored texels, and a filter decides the colour there. Nearest takes the texel the point falls in — blocky, but honest, and right for pixel art. Bilinear blends the four texels around the point by distance, the smooth default. Bicubic fits a little curve through sixteen texels with Catmull-Rom weights, sharper than bilinear and able to overshoot slightly at edges, which reads as crispness. All three are a handful of lines over the texels.

The trap

A texel's centre is at (tx + 0.5, ty + 0.5), not at (tx, ty). The stored value is the colour at the middle of the cell, the same convention pixels have had since chapter 2. So every sampler works in what you can call texel-centre space: take the source coordinate, subtract 0.5, and now integer values land on texel centres and the fractional part is the blend. Forget the 0.5 and nothing looks broken — the image still draws, still smooth — but it's shifted half a texel up and to the left, and every resample compounds it. You catch it with one test that has no tolerance for it: draw the image through the identity transform and it must come back bit-for-bit identical, under every filter. With the offset wrong, bilinear through the identity blends each pixel with its neighbour instead of reproducing it, and the test fails on the first pixel. That's the whole value of the identity case — it's the one input where guessing shouldn't happen at all, so any guessing shows.

§ 11.3 The image as a paint, and which way you walk

Here's the move that makes it all work. You might think to draw an image you'd loop over its texels and splat each onto the canvas. Try it and you get gaps where the image is magnified — the texels spread out and leave holes — and a mess where it's rotated. The fix is to loop over the destination pixels instead, and for each one ask "where in the source did you come from?" That's the matrix inverted: the transform m maps image space to device space, so inverse(m) maps a device pixel back to the point in the image to sample. Every output pixel gets filled exactly once, no gaps, no matter the transform.

image_paint(img, m, filter, extend):     // m places the image on the canvas
  return a paint that, at device (x, y):
    src ← inverse(m) · point(x, y)       // walk backward into the image
    return sample(img, src.x, src.y, filter, extend)

And because image_paint is a Paint, it needs no new drawing code: paint_fill from chapter 10 already samples a paint at every covered pixel. An image is now the same kind of thing as a gradient, which is what chapter 10 promised — solid, gradient, image, all one interface. The scenarios pin the identity as bit-exact, then place the image with a translation and a scale and check the inverse lands on the right texel.

§ 11.4 Making it smaller is a different problem

Everything so far is about magnification, where you have too few samples and interpolate between them. Minification is the reverse and it's genuinely a different problem, not the same filter run backward. When an image is drawn at a tenth its size, each output pixel covers a hundred source texels, and any of the filters above looks at only a handful of them — so it reports whatever those few happen to be and ignores the rest. Drag a fine checkerboard down to a small size that way and it doesn't average to grey, it breaks into swirling moiré, because which texels the sampler happens to hit changes from pixel to pixel. The output pixel should be the average of everything it covers, and a point sample is not that average.

The standard fix is a mip pyramid: precompute the image at half size, then half of that, down to a single pixel, each level the box-average of the one above. downsample(img) is that halving; mip_chain(img) is the whole stack. To draw the image minified, read from the level whose texels are about the size of an output pixel, so a single bilinear tap is already averaging the right amount of source — mip_level_for picks it from the scale factor, which chapter 4's approx_scale pulls out of the matrix. A box downsample preserves the average exactly, so a level and its parent agree on the picture's overall colour, and the scenarios pin that. This is the sense in which one filter can't serve both jobs: magnification reconstructs detail that isn't there, minification throws away detail that is, and they pull in opposite directions.

Why premultiplied, again

Every filter here is a weighted average of texels, and chapter 9 already showed that averaging straight-alpha pixels drags the stored colour of transparent texels into the result. So images store premultiplied pixels and the samplers blend premultiplied, which is why downsample and lerp_pixel add up r, g, b, a alike. For the opaque photos in this chapter it makes no visible difference; the first time you resample a cut-out with a soft edge, it's the difference between a clean edge and a grey fringe.

In the GUI

Photoshop's resample dropdown is this chapter's filter list under marketing names: Nearest Neighbor is nearest, Bilinear is bilinear, and Bicubic Smoother versus Bicubic Sharper is the enlarge-versus-reduce split — smoother reconstructs, sharper prefilters. The menu even tells you which to pick for growing and which for shrinking.

§ 11.5 Putting it together

The plate is the smallest honest demonstration there is: one tiny image, magnified hard, by two filters. An 8-by-8 sprite — built as a canvas, written to a PPM and read straight back, so the round trip is real — blown up twenty times. Nearest on the left keeps every hard edge, twenty device pixels to a texel, the look of pixel art. Bilinear on the right blends across the texel boundaries into smooth ramps. Same eight-by-eight source, same transform, one line different.

two_filters():
  s ← sprite()                           // the 8×8 image, round-tripped through a PPM
  left  ← paint s, scaled 20×, with "nearest"    // image_paint(s, scaling(20,20), "nearest")
  right ← paint s, scaled 20×, with "bilinear"
  return side_by_side(left, right)

plate_11():
  return two_filters()

An image is a paint, resampling walks backward through the inverse, and shrinking wants a pyramid. That's the last of the paints. What's left in this part is the machinery that decides where paint is allowed to land and how whole stacks of it combine: clipping, masks and groups, chapter 12, which turns out to need almost no new code at all, because the coverage buffer you built in chapter 2 was the right idea all along.
