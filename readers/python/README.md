# 2D Renderer Challenge: Python Implementation

Python 3 implementation of chapter 0 through chapter 25 and the epilogue of the 2D Renderer Challenge, using only the Python standard library (the `json` module is used to load fonts in chapters 16, 18 and 19; `xml.etree.ElementTree` is chapter 20's XML library; `fractions.Fraction` and `heapq` back chapter 22's exact Bentley-Ottmann sweep; `bisect` backs chapter 24's coarse stage). Chapter 0 is prose only and has no scenarios; the epilogue draws the book's own cover, `book_cover()`, from nothing but chapters already written.

## Build

No build step required. The implementation uses only Python 3 stdlib.

Chapters 24-25 catch-up: chapters 1 through 23's own 827 scenarios were re-run unmodified before touching anything and all passed, so this pass needed no catch-up fixes to the existing chapters — every scenario chapters 24 and 25 needed was new. Second chapter 24-25 catch-up: `features/chapter24-*.feature` and `features/chapter25-*.feature` gained three scenarios since the pass above — a brush stroke's opacity cap ("Opacity caps the stroke however often it crosses itself"), three-ink dithering ("Three inks"), and median cut's tie-breaks ("Median cut's ties", pinning the widest-channel tie going to red over green over blue and the box-selection tie going to the earliest box). `chapter24-shader.feature`'s scenario also started passing `radial_gradient`'s mode explicitly as `"pad"` (previously it relied on the default the first pass added), and chapter 24's plate prose renamed its star helper from `plate_star()` to `centred_star()` since it clashes with chapter 22's `plate_star()` in this runner's flat namespace. Chapter 20/21 catch-up: this pass also found and fixed a chapter 13 bug that a new `chapter13-stroke.feature` scenario ("A round cap is a semicircle of sixteen steps, whatever the rounding") exposed — `_arc_steps` computed `ceil(delta / (pi/16))` with no epsilon, so a semicircle's floating-point sweep (`16.000000000000004` on this machine) rounded up to 17 steps instead of 16. Chapter 15's reference images were re-diffed as instructed (rebuilt `even-marks.ppm`, `dash-strip.ppm`, `spiral-dashes.ppm`, `plate-15.ppm`) and all four came back at `max_channel_difference` 0 — no drift found.

The chapter 18-19 catch-up pass (611 to 616 scenarios) fixed one bug in `caret_positions`: it recorded a cluster's checkpoint *before* applying the kern adjustment for the upcoming glyph, instead of after, unlike `position()`'s own kern-then-place-then-advance order. It went unnoticed until `chapter19-position.feature` gained "A mark between two glyphs neither moves the pen nor breaks their kern pair", the first scenario with a kerned pair whose caret checkpoint falls between the kerned glyphs. See `FEEDBACK.md` for details.

Chapter 18's font loader (`load_font`, unchanged from chapter 16) already read `kern` as an optional JSON section; chapter 19 added `joining`, `forms`, `marks` and `anchors` as further optional sections that `Font` and `load_font` now carry (empty by default), read by `reference/chapter-19/dejavu-arabic.json`. The `test_runner.py` step parser had a latent bug from chapter 1 that chapter 19 exposed and this catch-up pass fixed: it split each step line on `.split()`/`' '.join()`, which silently collapsed multiple consecutive spaces inside a quoted string literal (e.g. `itemize("  12 ")`) down to one. No earlier chapter's scenarios happened to depend on preserving such whitespace exactly, so it went unnoticed for eighteen chapters; chapter 19's itemize scenario pins the *character offset* of text after a double space, which fails outright under the collapsed string. ## Implementation Notes

- Chapter 1 implements the canvas, colors, and PPM output
- Chapter 2 adds coverage buffers, shape queries, and antialiasing via supersampling
- Chapter 3 implements three line rendering approaches: Bresenham (fast, discrete), Wu (antialiased), and thick_line (coverage-based)
- Chapter 4 implements points, vectors, 3×3 matrices, and matrix transforms (translation, scaling, rotation, shearing); adds segment, union, transformed, and outline shapes; defines approx_scale for understanding stretch factors
- Chapter 5 adds `Path`: `move_to`/`line_to`/`close` build subpaths, `edges` lists every edge treating each subpath as closed, `bounds` is the axis-aligned box. `crossings` and `winding_at` answer insideness by ray casting, both using the half-open rule (`a.y <= y < b.y`) so a ray through a vertex counts once. `inside_nonzero`/`inside_evenodd` are the two fill rules built on `winding_at`; `filled(path, rule)` turns a path into a `Shape` chapter 2's rasterizer already knows how to draw. `rasterize_within` restricts chapter 2's `rasterize` to a path's bounding box. `star()`/`star_panel`/`star_centers`/`star_coverage`/`plate_05` render the pentagram plate.
- Chapter 6 replaces the per-pixel winding-number query with a classical scanline sweep. `edge_table` prepares every non-horizontal edge (`y_top`, `y_bottom`, `x_top`, `slope`, `direction`) sorted for the sweep; horizontal edges (`a.y == b.y` exactly) are dropped. `x_at` evaluates an edge's x at a height. `crossings_on_row` and `spans_from_crossings` turn a table into spans for one row; `fill_span` paints the pixels whose centers fall in a half-open span. `fill_path_aliased` is the full sweep with an active-edge list, producing a 0/1 coverage buffer identical to chapter 5's `rasterize_centers(filled(path, rule), w, h)` (checked directly by scenarios via `max_coverage_difference`). `transform_path` carries a path through a matrix without touching the original. `unit_star`/`spiral`/`plate_06` render the spiral plate of 24 stars.
- Chapter 7 replaces the center-sample/sweep fill with an analytic (signed-area) rasterizer. `Accumulator`/`accumulator(w, h)` holds two floats per cell, `area` and `cover`; `add_cell` deposits into one cell, folding a deposit left of the buffer onto column 0 as pure cover and dropping one right of the buffer. `accumulate_row` deposits one edge's piece within a single row, sharing its signed height across the cells it crosses by width and weighting each cell's area by the trapezoid midpoint rule. `accumulate` walks a whole edge down the rows it crosses (clipped to the buffer), with sign `+1` when the edge's first point has the larger `y` (heading up the canvas) and `-1` otherwise; horizontal edges deposit nothing. `resolve` sweeps each row left to right, turning the running cover-sum plus each cell's own area into a winding number, and `apply_rule` folds that (possibly fractional) winding into coverage — `min(1, |w|)` for `"nonzero"`, a triangle wave for `"evenodd"`. `fill_path(p, rule, w, h)` is the fill from here on, replacing `fill_path_aliased`; `polygon_area` is the shoelace formula, used by the scenarios to check the fill's total ink against the shape's exact area. `needle_path`/`needles`, `soft_square`, `star_exact`, `spiral_smooth`, `rays`/`sunburst`/`plate_07` render chapter 7's plates.
- Chapter 8 adds Bezier curves and the SVG elliptical arc. `Curve`/`quadratic`/`cubic` hold a curve as its control points; `point_at` evaluates it by de Casteljau's repeated linear interpolation; `split_at` keeps the same construction's left and right edges to split a curve into two of the same degree; `derivative` evaluates the curve's hodograph (one degree lower) for the tangent vector; `transform_curve` takes every control point through a matrix. `curve_bounds` finds the tight axis-aligned box by solving each axis of the derivative for its roots in `(0, 1)` (linear for a quadratic, quadratic for a cubic) and evaluating the curve there and at both ends. `flatness` is the farthest an interior control point sits from the chord between the curve's ends; `flatten` recursively bisects with `split_at` until every piece is flat enough, returning the polyline's points; `flatten_into_path` appends a flattened curve to a path with `line_to`. `polyline_length`/`flatten_length` measure a polyline/flattened curve's length. `arc(x1, y1, rx, ry, phi, large_arc, sweep, x2, y2)` converts SVG's endpoint form to a center form (growing the radii together and setting `corrected` when they're too small to reach, and returning `None` for coincident endpoints or a zero radius); `arc_point` walks it. `teardrop`/`drops`, `petal`/`flower_at`/`flower`/`plate_08` render chapter 8's plates.
- Chapter 9 adds premultiplied pixels and compositing. `Pixel`/`pixel(r, g, b, a)` stores colour already scaled by alpha; `from_color`/`opaque` premultiply, `pixel_color` un-premultiplies (reading black for a fully transparent pixel), `pixel_alpha` reads the alpha, `CLEAR` is the fully-transparent pixel, `lerp_pixel` blends two pixels straight down their channels. `over(src, dst)` is source-over; `coefficients(op, a_s, a_d)` is the Porter-Duff `(Fa, Fb)` table for the twelve named operators, and `composite(op, src, dst)` applies them. `blend(mode, src, dst)` is source-over with the overlap passed through `blend_color(mode, backdrop, source)`, which dispatches to the twelve separable per-channel modes or, for `"hue"`/`"saturation"`/`"color"`/`"luminosity"`, to `_lum`/`_sat`/`_clip_color`/`_set_lum`/`_set_sat` (the standard `Lum`/`Sat`/`ClipColor`/`SetLum`/`SetSat` compositing-spec helpers). `layer(w, h)` is a buffer of premultiplied pixels; `paint_shape` paints a colour into one through a coverage buffer (chapter 2's `paint_through`, but landing on a layer instead of paper); `composite_layers` and `flatten_layer` composite two layers and flatten one onto an opaque backing colour. `porter_duff_table`/`plate_09`, `blend_strip`, and `seam` render chapter 9's plates — `seam()` renders at quarter scale (two triangles sharing a main-diagonal edge, `(4, 4)`-`(76, 76)` on an 80×80 canvas) and magnifies by 4 so the one-pixel-wide conflation seam reads clearly.
- Chapter 10 turns paint into a function of position. `Stop`/`stop(offset, color)` and `sample_stops(stops, t)` are the colour-stop table, found by binary search and blended in linear light. `extend(t, mode)` folds an out-of-range parameter back in for `"pad"`/`"repeat"`/`"reflect"`. `linear_gradient`/`linear_t` project a point onto an axis; `radial_gradient`/`radial_t` solve the interpolated-circle quadratic, taking the largest root with a non-negative radius (or `None` if the point is outside every circle in the family — the focal gradient's unreachable cone); `conic_gradient`/`conic_t` take the angle around a center as a fraction of a turn. `solid(color)` and `paint_at(paint, x, y)` round out the `Paint` protocol (a `None` from `radial_t` reads as the last stop, not black). `paint_fill(c, cov, paint)` is `paint_through` with the colour replaced by a `paint_at` sample per pixel. `three_gradients`/`plate_10` and `extend_strip` render chapter 10's plates (the sunset stop table and the two-stop extend-mode table were reverse-engineered from the reference PPMs — see FEEDBACK.md). `BAYER4`/`dither_threshold`/`to_byte_dithered`/`canvas_to_p6_dithered` add ordered dithering: nudge the scaled light value by the position's 4×4 Bayer-matrix threshold before the floor.
- Chapter 11 adds images and resampling. `Image`/`image(w, h, pixels)` is a flat, row-major grid of premultiplied pixels; `read_image(ppm)` parses a P6 PPM, decoding each byte from sRGB to linear light and storing it opaque. `image_texel(img, ix, iy, extend)` reads one texel with an out-of-range index folded back by `"clamp"`/`"repeat"`/`"reflect"` (a private `_wrap_index` helper). `sample_nearest` floors straight to a texel (no half-pixel offset — flooring the raw coordinate already finds the cell the point falls in); `sample_bilinear` and `sample_bicubic` work in texel-centre space (source coordinate minus 0.5) and blend with `lerp_pixel` / Catmull-Rom weights from `catmull(t)`. `image_paint(img, m, filter, extend)` is a `Paint` (dispatched in `paint_at`) that walks a device point back through `inverse(m)` before sampling — the reason resampling has to walk destination pixels, not source ones. `downsample(img)` box-averages a 2x2 block of premultiplied channels; `mip_chain(img)` halves down to a single pixel; `mip_level_for(scale)` is `max(0, floor(log2(1/scale)))`. `sprite()`/`two_filters()`/`plate_11()`/`three_filters()` render chapter 11's plates — the 8x8 sprite is built as a canvas and round-tripped through `canvas_to_p6`/`read_image` so the round trip is real.

- Chapter 13 turns a stroke into a fill: `stroke_to_path(path, width, cap, join, miter_limit)` builds, for each subpath, a rectangle per segment (`_seg_rect`), a join wedge per interior vertex (`_join_shape`, `"miter"`/`"round"`/`"bevel"`), and a cap shape per open end (`_cap_shape`, `"butt"`/`"round"`/`"square"`) — all as subpaths of one output path, meant to be filled `"nonzero"` with chapter 7's `fill_path`; there is no new rasterizer. `miter_length(d_in, d_out, h)` is the closed form `h / sin(theta / 2)`, `theta` the interior angle between the incoming direction reversed and the outgoing direction; the join construction itself finds the miter tip by intersecting the two offset edges and falls back to a bevel when that tip's distance from the vertex exceeds `miter_limit * h`. - Chapter 14 fits a real curve, not a polyline, to the parallel offset of a Bezier. `tangent_at(c, t)` is the unit derivative, nudged to `t ± 0.0001` where the derivative vanishes (a handle sitting on its anchor); `normal_at(c, t)` is that tangent turned a quarter turn toward +y (chapter 13's `_perp`, reused as-is — the same +h side); `offset_point(c, t, d)` steps `d` along it. `second_derivative(c, t)` and `curvature(c, t) = cross(v, a) / |v|^3` (signed like `cross`) feed `cusps(c, d)`, which finds where `1 - curvature * d` changes sign across 64 samples (`t = i/64`, `i = 0..64`) refined by 40 bisections each. `fit_offset(c, d)` is the one-cubic fit (two anchors at the offset endpoints, handle directions the curve's own end tangents, handle lengths solved from a 2x2 cross-product system so the fit passes through the true offset midpoint); - Chapter 15 cuts a path into dashes measured by arc length, not parameter. `path_length(p)` sums a path's own segments (a closed subpath's closing segment included, but *not* pretending every subpath is closed the way chapter 5's `edges` does). `arc_length_table(c, n)` is the running chord length through `n + 1` evenly spaced parameters; `arc_length(c, n)` is its last entry; `t_at_length(table, s)` binary-searches the table and interpolates linearly inside the spanning chord; `point_at_length`/`split_at_length` hand the found parameter to chapter 8. `normalize_pattern(pattern)` repeats an odd-length pattern so on/off keep alternating the same way every cycle, and returns `[]` (drawn solid) for a negative entry or a pattern summing to zero or less — the two cases that would otherwise hang a naive walk on a zero step. `dash(path, pattern, phase)` walks every subpath by arc length (closed subpaths walked around their closing segment too), skips zero-length segments, and joins a last dash that runs all the way back into the first into one subpath that turns the starting corner (or, if a single dash covers the whole loop, returns it as one closed subpath). `lopsided()` is the curve whose parameter lies about distance; `even_marks()`/`wave()`/`dash_strip()`/`golden_spiral()`/`spiral_dashes()`/`plate_15()` render chapter 15's plates — the golden spiral is seven quarter-circle cubics, each `(1+sqrt(5))/2` times the radius of the last, flattened into one open subpath so the dash walk never resets across a turn.
- All geometry calculations use floating-point coordinates
- Antialiasing uses 8×8 supersampling (64 samples per pixel)
- P6 binary PPM files are used for efficiency
- Matrix operations use exact arithmetic with component-wise tolerance comparison (0.0001)
- Transforms are composed in reverse order: C * B * A applies A first, then B, then C

`crossing_point(s, t)` is the exact rational crossing rounded to the grid with plain integer floor division (`(2*n + d) // (2*d)`, which Python already rounds toward `-inf`, so no separate "halves up" branch is needed). `find_splits(segs, method, st)` implements all three methods the chapter asks for: `"brute"` (every pair), `"sweep"` (an active list sorted by `lo`), and `"bentley-ottmann"` (an ordered status list, events kept exact as `fractions.Fraction` pairs so a rounding error can never misorder the sweep — see Feedback for the one subtlety this needed: a split's *continuation*, for the rest of the same sweep, has to stay at the exact crossing point, not the rounded grid point, or rounding can walk a piece's new "lo" past a point already queued ahead of it in the sweep). `merge_segments`/`split_segments` fold duplicate segments (adding windings, dropping ones that cancel) and loop the split-cut-merge cycle to a fixed point. `winding_beside`/`inside_rule`/`op_inside`/`keep_edges` classify each segment's two sides once no segment crosses another, and keep the ones on the result's boundary, pointed so the inside is on the right. `stitch(kept)` links the kept arrows into closed contours, breaking a multi-way tie at a shared vertex by turning the furthest right — an exact total order over all four quadrants built from `cross`'s sign (clockwise) and a fallback to `dot` at exactly 180 degrees, *not* `math.atan2`. `combine`/`simplify`/`point_lists` are the whole pipeline; - Chapter 23 answers "how far to the edge" instead of "how much of this pixel," and turns a startling amount of the book into one-line arithmetic on that number. `sd_circle`/`distance_to_segment`/`sd_box`/`sd_rounded_box`/`sd_polygon` are the five exact primitive fields, the last built on chapter 5's `winding_at` for its sign. `solve_cubic` is Cardano's formula (one real root) and the trigonometric form (three), falling back to the quadratic/linear cases when the leading coefficients vanish (as every flattened TrueType line segment's quadratic does); `distance_to_quadratic` solves it once per query, exactly, while `distance_to_cubic`/`nearest_t_cubic` fall back to Newton's method from nine seeds plus both ends (an end has to be tried on its own, because Newton started there can walk away toward a stationary point *inside* the curve — `brute_distance`, a 129-sample-plus-ternary-search ground truth, is what caught that this reader's first cut of the cubic case, which only used the nine seeds, was wrong at exactly that case). `Field`/`field`/`field_coverage`/`polygon_field` are the field itself and how it becomes coverage (`clamp(0.5 - d, 0, 1)`); `field_offset`/`field_stroke`/`field_union`/`field_intersection`/`field_difference`/`field_xor` are chapters 13, 14 and 22 for free, one line each. `smooth_min`/`field_smooth_union`/`fillet_field` round a crease between two shapes into a fillet no path in this book can express exactly. `edt_1d`/`distance_transform`/`field_from_coverage` are Felzenszwalb and Huttenlocher's O(n) exact squared-distance transform (parabolas' lower envelope, column-then-row), turning any coverage buffer — not just a path — into a field. `bake_box`/`bake_sdf` bake a glyph's ordinary signed distance into a small texture; `is_corner`/`color_edges`/`pseudo_distance`/`bake_msdf`/`bake_mtsdf` are Chlumsky's multi-channel field (three channels coloured so every corner's two edges share exactly one, recovering a sharp corner from three smooth numbers via `median3`); `sample_field`/`draw_baked`/`draw_effect` sample a baked field bilinearly in texel-center space and turn the interpolated distance back into ink. `peanut`/`min_of` are the chapter's own trap: `min` of two fields is the right zero line for a union but the wrong *distance* inside it, which only shows once you offset or stroke the result (pinned exactly by `chapter23-compose.feature`). `primitive_fields`/`error_map`/`fields_vs_paths`/`fillets`/`transform_demo`/`atlas_corners`/`trap_shrink`/`plate_field`/`plate_23`/`title` render the chapter's plates and title; several of them (the two glyph fields, the atlas bakes, `title`'s four full passes over a baked, multi-channel "DISTANCE") are the slowest renders in the book to date in an interpreted language — see Feedback, Timing.
- Chapter 24 writes five GPU-shaped algorithms and the one that goes wrong, as ordinary CPU code that obeys the GPU's rules (no sorting, no unbounded work per pixel, no shared state). `Stencil`/`stencil_buffer`/`triangle_winding`/`stencil_triangle`/`fan_anchor` are stencil-and-cover: a fan of signed triangles from an anchor point, one per path edge, whose winding numbers sum to exactly chapter 5's `winding_at` because the fan's spokes cancel under the half-open rule; `cover`/`stencil_at`/`winding_mismatches` read a stencil back. `loop_blinn_uv`/`inside_curve`/`curve_sign`/`curve_terms`/`loop_blinn_stencil`/`glyph_stencil` are Loop and Blinn's quadratic-without-flattening trick: a curve's three control points get the coordinates (0, 0), (1/2, 0), (1, 1), and `u² - v < 0` (with the `s > 0` guard that picks the chord's near side, not its mirror on the far side of the triangle) is the sliver between the curve and its chord, added or subtracted from the chord-fan stencil by the control triangle's own winding sign. `sample_pattern`/`msaa_coverage`/`sliver` are multisampling: 1, 4 (a rotated grid), 16 (sixteen rooks) and 64 (chapter 2's regular grid) sample positions per pixel, each a full `stencil_buffer` at that offset, which is why a nearly-horizontal edge needs the *rotation*, not just the count, to add real levels of coverage. `shade_tile`/`lcg_shuffle` show chapter 10's `paint_at` was already a pure shader by asking for a tile's colours in shuffled order and getting the same answers back. The compute pipeline (`encode_svg`/`Scene`/`flatten_stage`/`bin_stage`/`coarse_stage`/`fine_tile`/`run_pipeline`/`render_svg_gpu`/`cull_groups`/`max_group_depth`/`STACK_DEPTH`/`FineStats`) takes chapter 21's tiler apart into four stages that each read one array and write another: `encode_svg` is chapter 20's walker drawing nothing, answering a flat list of `Fill`/`Push`/`Pop` scene commands instead; `Scene` numbers every path (clip parts included) as a draw; `flatten_stage` turns every draw into segments; `bin_stage` deposits each segment's chapter 21 cells into the bin of the tile they land in, in segment order (bit-for-bit the same deposits chapter 21's accumulator would have made, just filed by tile instead of summed in place); `coarse_stage` turns each tile's bins into a command list (a `GPUTileDraw` per fill, classified exactly as chapter 21's `classify_tiles` would, and `cull_groups` drops any push/pop pair with no fill between them in that tile); `fine_tile` runs one tile's list into its own block, with a small stack of blocks for nested groups (`STACK_DEPTH` 2, `FineStats.spills` counting every push that found the stack already full); `run_pipeline` runs every tile, in raster order or `lcg_shuffle` order, and the two answer the same bytes — the test that proves the renderer would parallelize. `winding_color`/`plate_24`/`msaa_demo`/`spill_map`/`tiger_assembly` render the chapter's plate and its three extra demos, all four byte-exact against `reference/chapter-24/` on the first attempt once the pipeline's classification logic was lifted from chapter 21's directly (see Feedback for the two small chapter 10/API gaps this chapter's own scenarios surfaced, not bugs in existing chapters).
- Chapter 25 is the raster-editor detour: the same coverage machinery from chapter 2, with the geometry supplied by a hand instead of a path. `Brush`/`brush`/`dab_coverage`/`stamp_positions`/`stroke_mask`/`paint_stroke`/`wobbly_events`/`min_along` are brushes: a dab is a round coverage kernel (a hard disc inside `hardness * radius`, a straight ramp to nothing at `radius`); `stamp_positions` walks the pointer's own polyline and drops a dab every `spacing * 2 * radius` of arc length, carrying the leftover distance across events the way chapter 15 carries dashes across segments, which is what turns 25 wobbly pointer events into 99 evenly-spaced dabs instead of a string of beads. `bytes_at`/`FillStats`/`fill_stats`/`flood_mask`/`select_color`/`anti_alias_mask`/`bucket`/`ring_canvas`/`naive_depth` are the paint bucket: `flood_mask` is the scanline fill (a stack of row-runs, never more than one seed in flight for a solid region, unlike the four-line recursive version everyone writes first, which blows the Python call stack on anything bigger than a few hundred pixels — `naive_depth` states the trap's own number, that the recursion goes exactly as deep as the region is large). `median_cut`/`canvas_bytes`/`nearest_index`/`remap`/`threshold`/`ordered_dither`/`error_diffuse`/`indexed_canvas`/`ramp_canvas`/`mean_light`/`canvas_to_bmp8`/`read_bmp8` are quantization: Heckbert's median cut chooses a palette by repeatedly splitting the box with the widest channel at the point where half its *pixels* (not half its distinct colours) fall on each side; `error_diffuse` is Floyd-Steinberg run in linear light exactly like every other blend in this book, which is the one line that keeps a dithered ramp's average brightness correct (`0.500732` against the ramp's true `0.5`) where diffusing in encoded bytes — "the chapter 1 mistake again" — would have come out too light (this reader checked by mutating `error_diffuse` to work in encoded space: `chapter25-quantize.feature`'s dithering scenario caught it immediately); `canvas_to_bmp8`/`read_bmp8` round-trip an 8-bit indexed BMP byte for byte (bottom-up rows, each row's own zero padding to a multiple of 4 bytes). `marquee`/`add_selection`/`subtract_selection`/`intersect_selection`/`feather`/`FloatingSelection`/`float_selection`/`move_floating`/`drop_floating`/`History`/`history`/`history_fill`/`undo`/`redo`/`stored_pixels` are selection and undo, both reusing chapter 12's coverage-based clips and chapter 9's premultiplied layers almost unchanged; `history_fill` only ever saves the rectangle it's about to overwrite, which is what makes undo affordable. `plate_25`/`dither_strip`/`halo_demo`/`brush_demo`/`paint_by_script` render the chapter's plate and its four extra demos, all five byte-exact against `reference/chapter-25/` on the first attempt, `paint_by_script` included (a whole scene painted by nothing but this chapter's own tools, then quantized to 16 colours and round-tripped through a real BMP file).
- Chapter 0 is the book's prose-only orientation chapter: no `data-feature` blocks, no scenarios, nothing to implement.
