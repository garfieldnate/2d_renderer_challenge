# 2D Renderer Challenge: Python Implementation

Python 3 implementation of chapters 1 through 21 of the 2D Renderer Challenge, using only the Python standard library (the `json` module is used to load fonts in chapters 16, 18 and 19; `xml.etree.ElementTree` is chapter 20's XML library).

## Build

No build step required. The implementation uses only Python 3 stdlib.

## Run Tests

```sh
python3 test_runner.py
```

This runs all Gherkin scenarios from chapters 1 through 21, from every `.feature` file under `features/` (727 scenarios as of the latest catch-up pass: 617 through chapter 19 — 616 plus a new chapter 13 catch-up scenario, see below — plus 83 for chapter 20 and 21 for chapter 21, plus 6 more added to chapter 20 in the catch-up covered by `FEEDBACK.md`). Run it from this directory. All 727 pass, and every render from chapter 2 through chapter 21 is byte-exact against `reference/` (`max_channel_difference` of 0), including `aspect_demo.ppm` (chapter 20's viewBox/preserveAspectRatio plate): its scenario now fully specifies the source document (see `FEEDBACK.md`), so the render is built from that instead of reverse-engineered from the reference PPM. The three chapter 16 plate renders that used to miss the budget (`glyph.ppm`/`plate-16.ppm`/`flip.ppm`) are fixed now that §16.5 states each render's exact geometry and inks: the control-polygon hairline uses `dim = color(0.3, 0.3, 0.34)` with round joins (not the guessed `miter`), the on-curve squares use `cyan = color(0.2, 0.75, 0.9)` (not `INKS[1]`), and `flip_trap`'s baseline guide is a proper 1-wide hairline stroke drawn over the glyph, not a 2-pixel-thick filled rectangle drawn under it.

Chapter 20/21 catch-up: this pass also found and fixed a chapter 13 bug that a new `chapter13-stroke.feature` scenario ("A round cap is a semicircle of sixteen steps, whatever the rounding") exposed — `_arc_steps` computed `ceil(delta / (pi/16))` with no epsilon, so a semicircle's floating-point sweep (`16.000000000000004` on this machine) rounded up to 17 steps instead of 16. Fixed by subtracting `0.000000001` before the ceiling, matching the book's own stated rule. `test_runner.py`'s `parse_comparison` also needed rewriting: its regex split a step on the *first* `=`/`<`/`>` it found, which chapter 20's scenarios broke immediately, since `shape_commands(parse_xml("<rect width='10' .../>")) = 5` has an `=` inside the quoted XML attribute value, before the real comparison operator. Replaced with a character scanner that tracks quotes and bracket depth and only treats an operator (or `±`) found outside both as real. Chapter 15's reference images were re-diffed as instructed (rebuilt `even-marks.ppm`, `dash-strip.ppm`, `spiral-dashes.ppm`, `plate-15.ppm`) and all four came back at `max_channel_difference` 0 — no drift found.

The chapter 18-19 catch-up pass (611 to 616 scenarios) fixed one bug in `caret_positions`: it recorded a cluster's checkpoint *before* applying the kern adjustment for the upcoming glyph, instead of after, unlike `position()`'s own kern-then-place-then-advance order. It went unnoticed until `chapter19-position.feature` gained "A mark between two glyphs neither moves the pen nor breaks their kern pair", the first scenario with a kerned pair whose caret checkpoint falls between the kerned glyphs. See `FEEDBACK.md` for details.

Chapter 18's font loader (`load_font`, unchanged from chapter 16) already read `kern` as an optional JSON section; chapter 19 added `joining`, `forms`, `marks` and `anchors` as further optional sections that `Font` and `load_font` now carry (empty by default), read by `reference/chapter-19/dejavu-arabic.json`. The `test_runner.py` step parser had a latent bug from chapter 1 that chapter 19 exposed and this catch-up pass fixed: it split each step line on `.split()`/`' '.join()`, which silently collapsed multiple consecutive spaces inside a quoted string literal (e.g. `itemize("  12 ")`) down to one. No earlier chapter's scenarios happened to depend on preserving such whitespace exactly, so it went unnoticed for eighteen chapters; chapter 19's itemize scenario pins the *character offset* of text after a double space, which fails outright under the collapsed string. Fixed by splitting only on the first run of whitespace (to separate the keyword) and keeping the rest of the line intact.

## Implementation Notes

- Chapter 1 implements the canvas, colors, and PPM output
- Chapter 2 adds coverage buffers, shape queries, and antialiasing via supersampling
- Chapter 3 implements three line rendering approaches: Bresenham (fast, discrete), Wu (antialiased), and thick_line (coverage-based)
- Chapter 4 implements points, vectors, 3×3 matrices, and matrix transforms (translation, scaling, rotation, shearing); adds segment, union, transformed, and outline shapes; defines approx_scale for understanding stretch factors
- Chapter 5 adds `Path`: `move_to`/`line_to`/`close` build subpaths, `edges` lists every edge treating each subpath as closed, `bounds` is the axis-aligned box. `crossings` and `winding_at` answer insideness by ray casting, both using the half-open rule (`a.y <= y < b.y`) so a ray through a vertex counts once. `inside_nonzero`/`inside_evenodd` are the two fill rules built on `winding_at`; `filled(path, rule)` turns a path into a `Shape` chapter 2's rasterizer already knows how to draw. `rasterize_within` restricts chapter 2's `rasterize` to a path's bounding box. `star()`/`star_panel`/`star_centers`/`star_coverage`/`plate_05` render the pentagram plate.
- Chapter 6 replaces the per-pixel winding-number query with a classical scanline sweep. `edge_table` prepares every non-horizontal edge (`y_top`, `y_bottom`, `x_top`, `slope`, `direction`) sorted for the sweep; horizontal edges (`a.y == b.y` exactly) are dropped. `x_at` evaluates an edge's x at a height. `crossings_on_row` and `spans_from_crossings` turn a table into spans for one row; `fill_span` paints the pixels whose centers fall in a half-open span. `fill_path_aliased` is the full sweep with an active-edge list, producing a 0/1 coverage buffer identical to chapter 5's `rasterize_centers(filled(path, rule), w, h)` (checked directly by scenarios via `max_coverage_difference`). `transform_path` carries a path through a matrix without touching the original. `unit_star`/`spiral`/`plate_06` render the spiral plate of 24 stars.
- Chapter 7 replaces the center-sample/sweep fill with an analytic (signed-area) rasterizer. `Accumulator`/`accumulator(w, h)` holds two floats per cell, `area` and `cover`; `add_cell` deposits into one cell, folding a deposit left of the buffer onto column 0 as pure cover and dropping one right of the buffer. `accumulate_row` deposits one edge's piece within a single row, sharing its signed height across the cells it crosses by width and weighting each cell's area by the trapezoid midpoint rule. `accumulate` walks a whole edge down the rows it crosses (clipped to the buffer), with sign `+1` when the edge's first point has the larger `y` (heading up the canvas) and `-1` otherwise; horizontal edges deposit nothing. `resolve` sweeps each row left to right, turning the running cover-sum plus each cell's own area into a winding number, and `apply_rule` folds that (possibly fractional) winding into coverage — `min(1, |w|)` for `"nonzero"`, a triangle wave for `"evenodd"`. `fill_path(p, rule, w, h)` is the fill from here on, replacing `fill_path_aliased`; `polygon_area` is the shoelace formula, used by the scenarios to check the fill's total ink against the shape's exact area. `needle_path`/`needles`, `soft_square`, `star_exact`, `spiral_smooth`, `rays`/`sunburst`/`plate_07` render chapter 7's plates.
- Chapter 8 adds Bezier curves and the SVG elliptical arc. `Curve`/`quadratic`/`cubic` hold a curve as its control points; `point_at` evaluates it by de Casteljau's repeated linear interpolation; `split_at` keeps the same construction's left and right edges to split a curve into two of the same degree; `derivative` evaluates the curve's hodograph (one degree lower) for the tangent vector; `transform_curve` takes every control point through a matrix. `curve_bounds` finds the tight axis-aligned box by solving each axis of the derivative for its roots in `(0, 1)` (linear for a quadratic, quadratic for a cubic) and evaluating the curve there and at both ends. `flatness` is the farthest an interior control point sits from the chord between the curve's ends; `flatten` recursively bisects with `split_at` until every piece is flat enough, returning the polyline's points; `flatten_into_path` appends a flattened curve to a path with `line_to`. `polyline_length`/`flatten_length` measure a polyline/flattened curve's length. `arc(x1, y1, rx, ry, phi, large_arc, sweep, x2, y2)` converts SVG's endpoint form to a center form (growing the radii together and setting `corrected` when they're too small to reach, and returning `None` for coincident endpoints or a zero radius); `arc_point` walks it. `teardrop`/`drops`, `petal`/`flower_at`/`flower`/`plate_08` render chapter 8's plates.
- Chapter 9 adds premultiplied pixels and compositing. `Pixel`/`pixel(r, g, b, a)` stores colour already scaled by alpha; `from_color`/`opaque` premultiply, `pixel_color` un-premultiplies (reading black for a fully transparent pixel), `pixel_alpha` reads the alpha, `CLEAR` is the fully-transparent pixel, `lerp_pixel` blends two pixels straight down their channels. `over(src, dst)` is source-over; `coefficients(op, a_s, a_d)` is the Porter-Duff `(Fa, Fb)` table for the twelve named operators, and `composite(op, src, dst)` applies them. `blend(mode, src, dst)` is source-over with the overlap passed through `blend_color(mode, backdrop, source)`, which dispatches to the twelve separable per-channel modes or, for `"hue"`/`"saturation"`/`"color"`/`"luminosity"`, to `_lum`/`_sat`/`_clip_color`/`_set_lum`/`_set_sat` (the standard `Lum`/`Sat`/`ClipColor`/`SetLum`/`SetSat` compositing-spec helpers). `layer(w, h)` is a buffer of premultiplied pixels; `paint_shape` paints a colour into one through a coverage buffer (chapter 2's `paint_through`, but landing on a layer instead of paper); `composite_layers` and `flatten_layer` composite two layers and flatten one onto an opaque backing colour. `porter_duff_table`/`plate_09`, `blend_strip`, and `seam` render chapter 9's plates — `seam()` renders at quarter scale (two triangles sharing a main-diagonal edge, `(4, 4)`-`(76, 76)` on an 80×80 canvas) and magnifies by 4 so the one-pixel-wide conflation seam reads clearly.
- Chapter 10 turns paint into a function of position. `Stop`/`stop(offset, color)` and `sample_stops(stops, t)` are the colour-stop table, found by binary search and blended in linear light. `extend(t, mode)` folds an out-of-range parameter back in for `"pad"`/`"repeat"`/`"reflect"`. `linear_gradient`/`linear_t` project a point onto an axis; `radial_gradient`/`radial_t` solve the interpolated-circle quadratic, taking the largest root with a non-negative radius (or `None` if the point is outside every circle in the family — the focal gradient's unreachable cone); `conic_gradient`/`conic_t` take the angle around a center as a fraction of a turn. `solid(color)` and `paint_at(paint, x, y)` round out the `Paint` protocol (a `None` from `radial_t` reads as the last stop, not black). `paint_fill(c, cov, paint)` is `paint_through` with the colour replaced by a `paint_at` sample per pixel. `three_gradients`/`plate_10` and `extend_strip` render chapter 10's plates (the sunset stop table and the two-stop extend-mode table were reverse-engineered from the reference PPMs — see FEEDBACK.md). `BAYER4`/`dither_threshold`/`to_byte_dithered`/`canvas_to_p6_dithered` add ordered dithering: nudge the scaled light value by the position's 4×4 Bayer-matrix threshold before the floor.
- Chapter 11 adds images and resampling. `Image`/`image(w, h, pixels)` is a flat, row-major grid of premultiplied pixels; `read_image(ppm)` parses a P6 PPM, decoding each byte from sRGB to linear light and storing it opaque. `image_texel(img, ix, iy, extend)` reads one texel with an out-of-range index folded back by `"clamp"`/`"repeat"`/`"reflect"` (a private `_wrap_index` helper). `sample_nearest` floors straight to a texel (no half-pixel offset — flooring the raw coordinate already finds the cell the point falls in); `sample_bilinear` and `sample_bicubic` work in texel-centre space (source coordinate minus 0.5) and blend with `lerp_pixel` / Catmull-Rom weights from `catmull(t)`. `image_paint(img, m, filter, extend)` is a `Paint` (dispatched in `paint_at`) that walks a device point back through `inverse(m)` before sampling — the reason resampling has to walk destination pixels, not source ones. `downsample(img)` box-averages a 2x2 block of premultiplied channels; `mip_chain(img)` halves down to a single pixel; `mip_level_for(scale)` is `max(0, floor(log2(1/scale)))`. `sprite()`/`two_filters()`/`plate_11()`/`three_filters()` render chapter 11's plates — the 8x8 sprite is built as a canvas and round-tripped through `canvas_to_p6`/`read_image` so the round trip is real.
- Chapter 12 adds clipping, soft masks, and groups, reusing chapter 2's coverage buffer and chapter 9's layers almost unchanged. `multiply_coverage(a, b)` clips one coverage buffer by another, cell by cell; `full_clip(w, h)` is coverage 1 everywhere (a no-op clip); `clip_path(p, rule, w, h)` is only `fill_path` under a different name, and `clip_rect` builds a rectangle path and clips to it. `soft_mask(cx, cy, r, w, h)` is a linear radial falloff, `clamp(1 - distance/r)`. `set_layer_pixel`/`layer_pixel` read and write a layer's premultiplied pixels directly; `push_group(w, h)` is `layer(w, h)`; `paint_into(lyr, cov, color, opacity)` paints through a coverage buffer scaled by an overall opacity and returns the layer; `scale_opacity(lyr, opacity)` scales every premultiplied channel (rgb and alpha alike); `pop_group_with_opacity(group, base, opacity)` fades the whole group once with `scale_opacity` and composites it over `base` with `composite_layers("src-over", ...)`, which is why a group's opacity resolves its own internal overlaps before fading, unlike applying opacity to each child. `opacity_plate()`/`plate_12()` render the group-opacity plate (`per_child()` at 50% each vs. `group_opacity()` opaque-then-faded); `clip_demo()` clips a `unit_star()` (radius 60, centred in a 150x150 panel) to a 45-radius circle on the left and a 70-radius soft mask on the right — the star radius, clip radius, mask radius and centre were reverse-engineered from the reference PPM (see FEEDBACK.md), since the chapter gives no pseudocode for this render.
- Chapter 13 turns a stroke into a fill: `stroke_to_path(path, width, cap, join, miter_limit)` builds, for each subpath, a rectangle per segment (`_seg_rect`), a join wedge per interior vertex (`_join_shape`, `"miter"`/`"round"`/`"bevel"`), and a cap shape per open end (`_cap_shape`, `"butt"`/`"round"`/`"square"`) — all as subpaths of one output path, meant to be filled `"nonzero"` with chapter 7's `fill_path`; there is no new rasterizer. `miter_length(d_in, d_out, h)` is the closed form `h / sin(theta / 2)`, `theta` the interior angle between the incoming direction reversed and the outgoing direction; the join construction itself finds the miter tip by intersecting the two offset edges and falls back to a bevel when that tip's distance from the vertex exceeds `miter_limit * h`. Degenerate inputs are handled explicitly: `_dedupe_points` drops consecutive duplicate points before any direction is computed (the division-by-zero the chapter warns about), and a subpath left with a single point is a dot — a filled disc for a round cap, a square for a square cap, nothing for butt. `chevron()` is the plate's three-point V, used to compare join styles on the same corner. `joins_plate()`/`plate_13()`/`caps_demo()` render chapter 13's plates, each panel a gray `fill_path` of the generated outline with the outline itself redrawn over it in magenta via chapter 3's `line_wu` (which takes integer endpoints, so the outline's coordinates are rounded with `round_half_up` first). Every piece `stroke_to_path` emits is oriented through a shared `_emit` helper that reverses a piece's points when its signed area (`_signed_polygon_area`, and `polygon_area` itself, now **signed** rather than `abs`-ed — see Feedback) comes out positive, so every piece winds counterclockwise on screen and overlapping pieces add under nonzero instead of cancelling; the round join's arc sweeps the short way round a vertex by taking the wrapped angular difference between its two offset points, not by inferring direction from the turn's sign. `u_turn()` is nine points on the upper half of a circle of radius 10 about `(50, 50)`, from 180 to 360 degrees in steps of 22.5, used to stroke a tight bend 40 wide and check the whole bend stays solid.
- Chapter 14 fits a real curve, not a polyline, to the parallel offset of a Bezier. `tangent_at(c, t)` is the unit derivative, nudged to `t ± 0.0001` where the derivative vanishes (a handle sitting on its anchor); `normal_at(c, t)` is that tangent turned a quarter turn toward +y (chapter 13's `_perp`, reused as-is — the same +h side); `offset_point(c, t, d)` steps `d` along it. `second_derivative(c, t)` and `curvature(c, t) = cross(v, a) / |v|^3` (signed like `cross`) feed `cusps(c, d)`, which finds where `1 - curvature * d` changes sign across 64 samples (`t = i/64`, `i = 0..64`) refined by 40 bisections each. `fit_offset(c, d)` is the one-cubic fit (two anchors at the offset endpoints, handle directions the curve's own end tangents, handle lengths solved from a 2x2 cross-product system so the fit passes through the true offset midpoint); `offset_error` is the worst miss at 17 matched parameters; `distance_to_curve(c, p)` is honest point-to-curve distance (65 samples, 32 rounds of ternary search between neighbours). `sub_curve`/`offset_curve` split a curve at its cusps and recursively halve each piece (capped at depth 16) until `fit_offset` is within tolerance; `offset_distance_error` samples 100 points along the result and checks each is `|d|` from the original, which is the property that fails on purpose inside a fold. `stroke_curve_to_path(c, width, cap, tolerance)` builds one closed outline — the `+h` offset flattened forward, the end cap (chapter 13's `_cap_shape`, walked as points), the `-h` offset flattened backward, the start cap — deduped and closed, versus `flatten_then_stroke` (flatten first, chapter 13's stroker with round joins) for comparison. `hairpin()`/`arch()` are the chapter's two demonstration curves; `two_strokes()`/`fold_demo()`/`offsets_plate()`/`plate_14()` render its plates, each panel a `fill_path` of an outline in gray with the outline's own edges redrawn in magenta via `line_wu` — using chapter 1's `round_half_up` (`floor(v + 0.5)`), the same halves-up rule chapter 13 uses, because the hairpin's offset outline has two points that land exactly on a half-integer row (`(80, 42.5)` and `(80, -17.5)`) and the reference renders resolve both ties the halves-up way, taking them to `43` and `-17` (see Feedback: this catch-up pass found the code using Python's built-in `round()`, round-half-to-even, which drew the tip a row off).
- Chapter 15 cuts a path into dashes measured by arc length, not parameter. `path_length(p)` sums a path's own segments (a closed subpath's closing segment included, but *not* pretending every subpath is closed the way chapter 5's `edges` does). `arc_length_table(c, n)` is the running chord length through `n + 1` evenly spaced parameters; `arc_length(c, n)` is its last entry; `t_at_length(table, s)` binary-searches the table and interpolates linearly inside the spanning chord; `point_at_length`/`split_at_length` hand the found parameter to chapter 8. `normalize_pattern(pattern)` repeats an odd-length pattern so on/off keep alternating the same way every cycle, and returns `[]` (drawn solid) for a negative entry or a pattern summing to zero or less — the two cases that would otherwise hang a naive walk on a zero step. `dash(path, pattern, phase)` walks every subpath by arc length (closed subpaths walked around their closing segment too), skips zero-length segments, and joins a last dash that runs all the way back into the first into one subpath that turns the starting corner (or, if a single dash covers the whole loop, returns it as one closed subpath). `lopsided()` is the curve whose parameter lies about distance; `even_marks()`/`wave()`/`dash_strip()`/`golden_spiral()`/`spiral_dashes()`/`plate_15()` render chapter 15's plates — the golden spiral is seven quarter-circle cubics, each `(1+sqrt(5))/2` times the radius of the last, flattened into one open subpath so the dash walk never resets across a turn.
- All geometry calculations use floating-point coordinates
- Antialiasing uses 8×8 supersampling (64 samples per pixel)
- P6 binary PPM files are used for efficiency
- Matrix operations use exact arithmetic with component-wise tolerance comparison (0.0001)
- Transforms are composed in reverse order: C * B * A applies A first, then B, then C
- The Gherkin test harness (`test_runner.py`) compares lists and tuples element-wise with the usual 0.0001 tolerance, recursively, so a list of `(x, direction)` crossings or `(x0, x1)` spans compares each float with tolerance rather than falling back to Python's exact `==` (see Feedback, chapter 6, for why this needed fixing).
- Chapter 16 adds `Font`/`Glyph` (loaded by `load_font` from the JSON schema: `units_per_em`/`ascender`/`descender`/`line_gap`, `cmap`, and `glyphs` by name with `advance`/`contours`/`components`); `glyph_name`/`glyph_advance`/`glyph_count` read it. `implied_points(contour)` expands a TrueType contour's implicit on-curve midpoints (walking the loop with wraparound, so the last-to-first pair counts too) and rotates the result to start on an on-curve point; `contour_curves(contour)` turns that into chapter 8 quadratics, one per on-curve-to-on-curve span, a straight edge becoming a quadratic through its own midpoint. `component_matrix(t)` builds a `matrix3` from a component's six-number `[a, b, c, d, dx, dy]` the way TrueType applies it (`x' = a·x + c·y + dx`, `y' = b·x + d·y + dy`); `glyph_outline(font, name)` is a glyph's contours as quadratics (its own, plus each component's recursively through its matrix) — it returns one list of quadratics *per contour*, not one flat list, which is what lets `length(glyph_outline(font, "eacute")) = 3` mean "three contours" (two from `e`, one from `acute`). `glyph_bounds` unions chapter 8's `curve_bounds` over every quadratic of every contour; an empty glyph is `(0, 0, 0, 0)`. `text_matrix(font, size, x, y)` is the one place the y-up/y-down flip lives: `translation(x, y) * scaling(scale, -scale)`, `scale = size / units_per_em`. `contour_path`/`glyph_path` take an outline through a matrix, flatten in device space, and close each contour into a subpath — fill nonzero and a glyph's counters fall out for free, the same hole the pentagram's centre was in chapter 5. `glyph_plate()`/`plate_16()` render the letter `a` with its control polygon overlaid (on-curve points as filled squares in `cyan = color(0.2, 0.75, 0.9)`, off-curve as hollow circles in magenta via a stroked `circle_path`, implied on-curve points as smaller cyan squares, and the polygon itself as a hairline — chapter 14's stroke, butt caps, round joins, 1 wide, filled nonzero — in `dim = color(0.3, 0.3, 0.34)`, both named explicitly in §16.5). `composite_demo()`, `sizes()`, and `flip_trap()` are also pinned by §16.5's prose now (canvas size, em size, origin, baselines, and, for `flip_trap`, that its baseline guide is the same dim hairline drawn *over* the filled glyph, not a filled rectangle drawn under it); all five chapter 16 renders are byte-exact against `reference/chapter-16/`.
- Chapter 17 adds `subpixel_of(x)` (a pen position split into a whole pixel and a quarter, rounded to the nearest quarter and carried on rounding up to four) and `glyph_bitmap(font, name, size, subpixel)`, a `Bitmap` (`.coverage`/`.left`/`.top`, `.width`/`.height` read off the coverage buffer) sized to the glyph's own device bounds shifted by the quarter and rendered through a `text_matrix` whose origin is offset so the buffer's corner lands at `(0, 0)`. `paint_bitmap(canvas, bitmap, x, y, color, linear)` composites it at a whole-pixel pen, taking `linear` directly rather than the global switch, so the fudge-naming scenarios can show both lanes side by side. `glyph_cache()`/`cached_bitmap`/`cache_size` memoize by `(name, size, subpixel)`; `Atlas`/`atlas`/`atlas_add` shelf-pack bitmaps left to right, opening a new shelf below the tallest one so far when a bitmap doesn't fit the current row, answering `None` when it doesn't fit the atlas at all. `embolden(font, name, size, amount)` is the plain fill plus chapter 13's `stroke_to_path` of the same outline at width `amount`, coverages added and clamped to 1, in a bitmap grown a pixel all round. `LCD_TAPS`/`lcd_filter`/`lcd_coverage`/`paint_lcd` are the three-coverages-per-pixel machinery: `lcd_coverage` rasterizes through a matrix stretched 3× horizontally (not just shifted — the buffer really is the glyph three times wider) into a `3w`×`h` buffer, filters every row (zero-padded past the ends), and `paint_lcd` mixes red/green/blue each through its own stripe. `pen_advance`/`draw_text` round out the line-of-text mechanics used by the plates. `subpixel_strip()`, `smoothing_demo()`, and `lcd_plate()`/`plate_17()` matched the reference PPMs exactly (`max_channel_difference` 0) on the first reverse-engineered layout attempt.

- Chapter 19 is a small, honest shaper. `Font`/`load_font` (unchanged code, chapter 16's schema already had the hook) gained four more optional JSON sections for the Arabic font: `joining` (codepoint → Unicode joining type), `forms` (glyph name → {form → glyph name}), `marks` (glyph name → `(class, ax, ay)`), `anchors` (glyph name → {class → `(ax, ay)`}). `script_of`/`itemize` cut a string into single-script, single-direction `Item`s, a "common" character (space, digit, punctuation) joining the run before it (or the first run, or defaulting the whole string to `"latin"` if it's common throughout). `glyph_buffer`/`GlyphEntry`/`clusters` are the buffer chapter 16's cmap lookup starts from, one entry per character, each its own cluster. `apply_ligatures` walks the buffer left to right trying the font's rules longest-first and is genuinely non-recursive on its own output — a matched span is replaced and the scan continues *after* it, never re-examining the glyph it just produced. `joining_type`/`arabic_forms` implement Unicode's join-backward/join-forward rule exactly as stated (searching past `"transparent"` neighbours only, not past `"none"` ones), and `apply_forms` swaps each glyph for its positional form when the font's table has one. `is_mark`/`attach_marks` find each mark's nearest preceding non-mark base, set the mark's `(dx, dy)` to the difference of the two anchors, and hand the mark the base's cluster; `caret_positions` replays the same pen walk, but records the pen *before* each new cluster's first glyph is placed (which equals that glyph's own placement in `"ltr"`, but its right edge — the *previous* checkpoint — in `"rtl"`, since RTL places a glyph at its left edge after subtracting, not before). `ligature_demo()`/`forms_demo()`/`word_demo()`/`mixed_demo()`/`cluster_plate()`/`plate_19()` render the chapter's plates; - Chapter 20 renders SVG with nothing but the previous nineteen chapters. `parse_xml`/`attribute`/`children`/`find_by_id` wrap `xml.etree.ElementTree` (`XMLElement.name` strips the namespace off the tag). `read_number(s, i)`/`number_list(s)`/`read_flag(s, i)` are a small hand-rolled number reader (a plain regex over the *whole* attribute can't tell where one number ends and the next begins when the grammar allows `30-40` or `.5.5` or two packed arc flags with no separator at all); - Chapter 21 makes chapter 20 fast without changing a single byte it draws, which is the whole discipline: every optimization is checked against the untouched `render_svg` output before it's trusted. `stats()`/`fill_path_counted`/`draw_coverage_counted` count cells resolved and pixels blended instead of timing anything (wall-clock time isn't a valid test). `fill_bounds` is the floor/floor+1 window a path can reach; `fill_path_bounded` moves the path so that corner is the origin and fills only that window — ten lines, and it's most of the win, because chapter 7's fill otherwise resolves the whole canvas for a shape covering a few pixels. `classify_tiles`/`fill_path_tiled` cut the (bounded) canvas into 16-pixel tiles and, for tiles with no edge in them, read the *whole number* arriving at the tile's left edge off the running sum instead of resolving a single cell — but doing that check only across the rows a tile *shares with the path's own bounds*, and skipping the rest, is exactly the bug the chapter's trap warns about: a horizontal edge deposits nothing, so the rows above and below it never disagree if you never look at both, and the tile gets painted solid down past where the shape actually ends. (This bug shipped in the first draft of this reader's `_classify_or_fill_tiles` and was caught immediately by `chapter21-tiles.feature`'s very first scenario, "A square leaves its middle tiles solid" — see Feedback.)
