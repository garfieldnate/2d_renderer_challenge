## New or changed scenarios

1. `chapter18-aligning.feature`: "The last line stays left even when it has
   spaces to stretch" -- a 150-measure justified paragraph whose last line
   ("over the lazy dog") does have a space, unlike the paragraph in the
   pre-existing scenario (whose breaking happens not to matter for the
   left-vs-justify question the same way). Added.
2. `chapter19-ligatures.feature`: "The longest rule that matches wins, on a
   font written by hand to have two" and "A result is never fed back into
   the rules" -- both new, against a new hand-written toy font (`a`, `b`,
   `c` with ligature rules `a b -> a_b`, `a b c -> a_b_c`, `a_b a -> a_b_a`).
   The third rule's parts include another rule's own result glyph name, so
   it can only ever match if a ligature result is fed back into the rule
   matcher. Added both, plus a shared `toyFont()`/`TOY_FONT_JSON` helper in
   `Chapter19Tests.java` (the JSON literal is reused by a third new scenario
   in `chapter19-position.feature`, so it isn't inlined three times).
3. `chapter19-marks.feature`: "shape chooses the forms before it looks for
   ligatures" -- shapes سلام (SALAAM) with `dejavu-arabic.json` and checks
   the lam-alef ligature (`lam_alef.fina`) comes out, which only works if
   `shape` applies `applyForms` before `applyLigatures` (the font's
   ligature rule is written in terms of post-forms glyph names like
   `lam.medi`). Added.
4. `chapter19-position.feature`: "A mark between two glyphs neither moves
   the pen nor breaks their kern pair" -- reuses the toy font, text `"a*b"`
   (`*` maps to a mark glyph `dot` with an anchor on `a`). Checks
   `shape`/`position`/`bufferAdvance`/`caretPositions` in `"ltr"`, and in
   `"rtl"` with `kerning` both `true` and `false`. This is the first
   scenario in the suite that exercises `"rtl"` with `kerning = true`,
   which the README's own note on `caretPositions` says was the exact blind
   spot that let a wrong formula pass every prior scenario. Added.

## What failed on the old code

Nothing. All 5 new scenarios pass against the existing `Layout.java` and
`Shaping.java` without any production-code change:

- `Layout.layoutParagraph` already forces a justified paragraph's last line
  to `"left"` unconditionally (not only when the last line lacks spaces),
  so scenario 1 was green on the first run.
- `Shaping.applyLigatures` already tries the font's rules longest-first at
  each buffer position and never re-matches a rule against its own output
  (the loop only ever reads from the original `buffer`, appending results
  to a separate `out` list), so scenarios 2a/2b were green on the first
  run.
- `Shaping.shape` already calls `applyForms` before `applyLigatures` (and
  `attachMarks` last), so scenario 3 was green on the first run.
- `Shaping.caretPositions`'s `"rtl"` branch already computes
  `run[i].x + the glyph's own advance` (the corrected formula the README's
  note describes deriving), not the discarded entry-point formula, so
  scenario 4 was green on the first run including the `kerning = true`
  case that no prior scenario exercised.

Manually hand-traced scenario 4's arithmetic against the toy font before
running it (kern -100/1000 units, mark anchor (300,700), size 10, em
1000) to make sure a passing result wasn't a coincidence of the specific
numbers chosen; the trace matches the implementation's actual code path,
not just its output.
